The Problem

Why Naive Context Compression Fails

  • Silent Fact Dropping: Truncation or aggressive summarizers drop critical dates, prices, and error codes.
  • Negation Inversion: Dropping "must not open Port 22" leaves "open Port 22", introducing critical security flaws.
  • Outdated Revisions: Older meeting times or promises are retained while later corrections are discarded.
  • Broken Code & Records: Code block splitting causes syntax crashes, while truncated JSON records cause parsing failures.
The Solution

How Context Surgeon Fixes It

  • Query-Aware Relevance: Ranks sections by term rarity and exact entity matches instead of blind position cutting.
  • Evidence Protection Rules: Automatically locks numbers, dates, negations, corrections, and linked identifiers.
  • Python Dependency Linking: Traverses symbol definitions to pull required helper functions automatically.
  • Budget Safety Warnings: When evidence cannot safely fit within the requested budget, it issues transparent warnings rather than silently hallucinating.

Architectural Deep Dive

The 5-Stage Deterministic Context Compression Pipeline

01

Stage 1: Multi-Modal Segmentation

Extracts identifiable context boundaries. Message conversation turns (User:, Assistant:), fenced code blocks, and JSON records are preserved as indivisible units.

02

Stage 2: Deduplication & Rarity Ranking

Hashes remove exact duplicate snippets. Calculates inverse term frequencies (TF-IDF rarity) and query identifier matches to score non-stopwords.

03

Stage 3: Evidence Protection & Expansion

Conservative protection locks numbers, dates, times, currency, and negations ("must not", "prohibited"). Symbol graphs automatically pull in referenced Python dependencies.

04

Stage 4: Token-Budget-Aware Selection

Greedily selects highest-priority sections under budget. If critical evidence exceeds the budget, it retains the evidence and emits a transparent budget warning.

05

Stage 5: Audit & Explanation

Provides complete decision transparency for every section: retained, removed, or deduplicated, with human-readable rationale and metrics.

Engineering Guarantees

  • Zero Silo LLM Requirement: The entire 5-stage compression pipeline runs locally on CPU in sub-10ms without requiring an LLM call or API key.
  • Immutability Guarantee: System instructions and user queries remain 100% bit-for-bit unchanged. Only supporting context is pruned.
  • Chronological Order: Retained sections are reassembled in their exact original chronological document sequence.
  • No Silent Truncation: If a budget is too small to safely fit facts, a warning is returned rather than risking hallucination.
